## 2. 通信プロトコル（ESP32 とのやり取り。v0.3.0 でも変更なし）

```
A5 5A | type(1) | seq(4) | len(2) | 本体(len バイト) | crc(2)       すべてリトルエンディアン
```

- `type`:
  - `0x01` = XY フレーム（本体 = x0,y0,x1,y1,... 各 u8）
  - `0x10` = **制御**（本体 1 バイトが命令。`0x01` = 再生が終わった）。ESP32 は、受け取るとすぐに待機パターンに切り替え、`EVENT end` を PC に返す。送るのは、**最後のフレームを表示し終えた時刻**（ループ再生とベンチマークでは送らない）
  - `0x02` は将来の XYZ 用に予約（ESP32 は今は読み捨てる）
- `seq`: パケットの通し番号（送るたびに +1）。ESP32 は、飛びを `lost` として数える
- `crc`: type 〜 本体 の CRC-16/CCITT-FALSE（多項式 0x1021、初期値 0xFFFF）。Python は `binascii.crc_hqx(data, 0xFFFF)`
- ESP32 は、1 秒ごとに `STAT ok=.. (+N/s) crc=.. len=.. tmo=.. lost=.. skip=.. passes/s=.. end=..` を送り返す（`end` = 終了の合図を受け取った回数）
- 終了の合図が届かなくても、1 秒以上フレームが届かなければ、ESP32 は待機の円を描く（CRT の焼き付き防止。PC が途中で止まったときの保険）

## 3. v0.3.0 の目的と完了条件

**目的**: PC で音声を鳴らしながら、同じ時刻の映像をオシロに出し、音と映像のずれを小さく保つ。

- [ ] `--loop` で、先頭に戻っても、音と映像が合っている

## 4. 同期の設計

### 4.1 時間の基準は「音声」

PC の時計と、音声デバイスの時計は、わずかに速さが違います（数百 ppm〜）。PC の時計で映像を送ると、数分で音とずれていきます。**音声が、今どこまで再生されたかを基準**にして、その位置のフレームを送ります。

### 4.2 式

```
今聞こえている音の位置   pos = S / sr + (now - T) - latency
送るフレーム番号         target = floor((pos + offset + lead) × fps)
```

| 記号 | 意味 | 値の出どころ |
|---|---|---|
| S | 音声コールバックが、これから出力するブロックの先頭のサンプル番号 | コールバックの中で記録 |
| T | そのコールバックが呼ばれた時刻（`time.perf_counter()`） | 同上 |
| sr | 音声のサンプリングレート | WAV のヘッダ（44100 など） |
| latency | 出力デバイスの遅延（秒） | `sounddevice` の `stream.latency` |
| offset | 手で合わせる補正（秒）。**+ にすると映像が先に出る** | `--offset-ms`、実行中の入力 |
| lead | 1 パケットの転送時間（秒）。自動 | `(2N + 11) × 10 / baud`（N=1000、921600bps で約 21.8ms） |
| fps | 映像のフレームレート | `.osa` のヘッダ |

- コールバックは 10〜20ms ごとにしか呼ばれないので、その間は PC の時計（`now - T`）で補間します。コールバックのたびに、音声の位置へ合わせ直すので、PC の時計の狂いは溜まりません
- `target` が、前に送ったフレームより 2 以上進んでいたら、間のフレームを**飛ばします**（遅れを取り戻す。`skipped` として数える）
- 音声は、**映像の長さにそろえます**（足りなければ無音で埋め、余れば切る）。ループの周期が、映像の長さになります

### 4.3 遅れの内訳（補正が必要な理由）

| 要素 | 大きさの目安 | 扱い |
|---|---|---|
| シリアルの転送（2011 バイト @921600bps） | 約 22ms | `lead` として自動で補正 |
| ESP32 の受信・描画の切り替わり | 数 ms | `offset` に含まれる |
| 音声デバイスの出力遅延 | 数十 ms | `latency` として補正（PortAudio の見積もり） |
| Bluetooth スピーカー・イヤホン | **100〜300ms** | **有線を使う**こと。使うなら `offset` で大きく補正 |
| オシロの表示 | ほぼ 0 | |

`latency` は、PortAudio の見積もりで、実際と違うことがあります。最終的には、**耳と目で `offset` を合わせます**（6章）。

## 5. プログラムの仕様

### 5.1 コマンド

```powershell
cd tools
pip install sounddevice           # 初回のみ（requirements.txt にも追記する）

# 音声の用意（変換した区間と同じ範囲を切り出す）
ffmpeg -ss 33 -t 35 -i badapple.mp4 -vn -ac 2 -ar 44100 -c:a pcm_s16le audio_clip.wav     # 35 秒のクリップ（main.osa 用）
ffmpeg -i badapple.mp4 -vn -ac 2 -ar 44100 -c:a pcm_s16le audio_full.wav                  # 全長（full.osa 用）

# 再生
python -m osaconv.play main.osa --audio audio_clip.wav --port COM6 --baud 921600
python -m osaconv.play full.osa --audio audio_full.wav --port COM6 --baud 921600 --offset-ms 0 --loop
```

**`.osa` と WAV は、同じ開始位置・同じ長さにそろえる**こと（`--start` と `-ss`、`--seconds` と `-t`）。

### 5.2 引数

| 引数 | 既定値 | 内容 |
|---|---|---|
| `osa`（位置引数） | | 映像（`.osa`） |
| `--audio` | （必須） | **16bit PCM の WAV**。mp3 などは不可（ffmpeg で変換する） |
| `--port` | （必須） | 例: `COM6` |
| `--baud` | 921600 | ESP32 の `BAUD` と同じ値にする |
| `--offset-ms` | 0 | `+` で映像を先に出す。`-` で遅らせる |
| `--loop` | なし | 最後まで行ったら先頭に戻る |
| `--reset-wait` | 2.0 | ポートを開いたあとに待つ秒数（ESP32 のリセット対策） |

### 5.3 実行中の操作

- ターミナルで `+10` や `-10` と入力して Enter → `offset` を 10ms 動かす（実行を止めずに合わせられる）
- 終了時（または Ctrl+C）に、最終の `offset` が表示される。その値を `--offset-ms` に渡す
- 1 秒ごとの表示: `[PC] t=.. frame=.. sent=.. skipped=.. offset=.. underflow=..`
  - `skipped` が増え続ける → PC か通信が間に合っていない
  - `underflow` が増える → 音声が途切れている（他のアプリを閉じる、`blocksize` を大きくする）

### 5.4 `play.py` の構成

| 名前 | 役割 |
|---|---|
| `AudioClock(sample_rate, latency_s, time_fn)` | `on_block(start_sample)` を音声コールバックで呼ぶ。`position()` が、今聞こえている音の位置（秒）。音声が始まる前は `None` |
| `load_wav(path)` | 16bit PCM の WAV を読み、`(int16 配列 [サンプル数, チャンネル数], サンプリングレート)` を返す |
| `fit_audio(data, n_samples)` | 音声の長さを、映像の長さにそろえる |
| `run_sender(ser, xy, fps, clock, ...)` | 4.2 の式でフレームを選び、パケットを送り続ける。`ser` は `write()`、`clock` は `position()` を持つもの（テストで差し替えられる） |
| `play_av(...)` | `sounddevice` の出力ストリームを開き、`run_sender` を動かす |

`stream.py` の `build_packet`、`open_port`、`_reader` を再利用しています。`sounddevice` は、`play_av` の中で読み込むので、テストには不要です。

## 6. 調整の手順（実機で必ず行う）

### 6.1 テスト用データで測る

```powershell
python scripts/make_sync_test.py          # sync_test.osa と sync_test.wav ができる
python -m osaconv.play sync_test.osa --audio sync_test.wav --port COM6 --loop
```

- 毎秒、**「ピッ」という音と、大きな四角のフラッシュ**（0.1 秒）が同時に出る設計
- スマホで、**オシロの画面とスピーカーが一緒に映る**ように動画を撮る
- 撮った動画をコマ送りで見て、「音が出始めたコマ」と「四角が出始めたコマ」の差を数える（スマホが 30fps なら 1 コマ ≈ 33ms、60fps なら 17ms）

| 見え方 | 対処 |
|---|---|
| 音より、**映像が遅い**（四角が音のあとに出る） | `offset` を **+** にする（映像を先に出す） |
| 音より、**映像が早い** | `offset` を **−** にする |

### 6.2 本番の動画で確認する

Bad Apple の、動きと音がはっきり合う場面（ドラムなど）を見て、実行中に `+10` / `-10` で微調整します。合ったら、最終の `offset` を控え、README に書きます。

### 6.3 長く再生してもずれないか

全長を `--loop` で 2 周ほど再生し、**最初と最後で、ずれが同じか**を確認します。広がるなら、4.1 の仕組みがどこかで崩れています（9章の「ずれが広がる」を参照）。

## 付録 A. v0.3.1（つなぎ線）の設計メモ

つなぎ線 = 輪郭と輪郭のあいだを、ビームが移動する軌跡。Z軸が無いので、今は、輪郭と同じ明るさで見える。

### 方法 1: ソフトで薄くする（ハード不要）

アナログオシロでは、線の明るさは**ビームの速さ**で決まる（遅いほど明るい）。つなぎ線に、点をほとんど割り当てなければ、ビームは一気に動き、線が薄くなる。

実装の方針（`path.py`）:

1. `_order_and_join` で、輪郭をつなぐとき、**つなぎ線の区間を記録**する（各頂点に「この頂点へ来る線分は、つなぎ線」という印）
2. `_resample` の「道のり」の計算で、つなぎ線の区間の長さを、実際の長さではなく、**小さな固定値**（例: 3〜4）として数える
3. その道のりを等間隔に N 分割し、点の位置は、各区間の中を線形に補間する
4. 副作用として、輪郭に使える点が増えるので、絵が細かくなる

試すところ: 固定値（`JUMP_COST`）を 1〜10 で変えて、実機で、つなぎ線の薄さを見る。**薄くなる程度は、実機のオシロで確かめるまで分からない。**

### 方法 2: Z軸入力で消す（ハード）

- **まず、SS-7802 の背面に Z軸入力（`Z AXIS INPUT` など）があるか**を確認する（私は未確認）。仕様（感度、極性、結合、帯域）も、取扱説明書で確認する
- ESP32 のデジタル出力ピン 1 本で、点灯・消灯を切り替える（DAC は X と Y で使用済み）。3.3V で足りるかは、Z軸の感度次第。足りなければ、トランジスタで電圧を上げる
- データ形式: `type = 0x02`（XYZ）。本体 = XY の `2N` バイト + **Z のビットマスク `ceil(N/8)` バイト**（1 点 1 ビット。N=1000 で 125 バイト増、約 6%）
- 変更箇所: `path.py`（つなぎ線の点に、Z=消灯の印）、`stream.py`（`0x02` で送る）、`osa_stream.ino`（`0x02` を受け取り、Z ピンを `dacWrite` と同時に切り替える）
- ESP32 の `TYPE_FRAME_XY` 以外は、今は読み捨てているので、`0x02` の分岐を足す

方法 1 → 足りなければ方法 2、の順がおすすめ。

## 付録 B. 付随する注意

- **CRT の焼き付き**: ビームを止めたまま長く置かない。`osa_stream.ino` は、待機中に円を動かしている。白紙のフレーム（輪郭が無いフレーム）は、画面中央に、N 個の同じ点を出す。長く続く白紙がある動画では注意する
- **ミニ PC（Ubuntu server）**: ポート名は `/dev/ttyUSB0`。音声は、サーバー版だと設定が必要（ALSA、PortAudio のライブラリ）。まず Windows で完成させ、必要になってから移す
- **`.gitignore`**: `*.wav`、`*.mp3`、`*.osa`、`*.mp4` は Git に入れない
